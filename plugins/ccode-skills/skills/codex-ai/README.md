# Codex-AI 协作技能

通过 Bash 直接调用 Codex CLI，快速处理复杂技术任务。

## 🚀 快速开始

### 基本使用

只需用自然语言描述你的需求，包含关键触发词即可：

```
你: "帮我审查一下当前的代码变更"
你: "设计一个高性能的缓存淘汰算法"
你: "分析这个系统的架构瓶颈"
你: "优化这个函数的性能"
```

### 触发词

| 场景 | 触发词 |
|------|--------|
| 代码审查 | 代码审查、review、code review |
| 算法设计 | 算法设计、复杂逻辑、algorithm design |
| 架构分析 | 架构分析、架构评审、architecture analysis |
| 性能优化 | 性能优化、瓶颈分析、performance optimization |

## 🤖 模型选择

技能会根据任务复杂度自动选择合适的模型：

### 简单任务 → gpt-5.1-codex-max

**适用场景**：
- 代码审查
- 简单重构
- 文档生成
- 常规 bug 修复

**特点**：响应快速、成本较低、适合日常开发

### 复杂任务 → gpt-5.2

**适用场景**：
- 复杂算法设计
- 架构评审
- 性能优化
- 多约束问题

**特点**：深度推理、处理复杂约束、适合关键决策

### 判断标准

| 维度 | 简单任务 | 复杂任务 |
|------|---------|---------|
| **目标** | 单一明确 | 多个约束 |
| **范围** | 局部修改 | 系统级设计 |
| **约束** | 简单清晰 | 多重权衡 |

## 💡 最佳实践

### ✅ 推荐做法

1. **提供完整上下文**
   - 明确约束条件（性能、内存、延迟）
   - 说明边界情况
   - 提供相��代码片段

2. **明确性能要求**
   - 具体的延迟目标（如 p99 < 100ms）
   - 吞吐量要求（如 10K req/sec）
   - 资源限制（如内存 < 1GB）

3. **验证后再实施**
   - 理解 Codex 的建议
   - 评估可行性
   - 测试验证
   - 逐步实施

### ❌ 避免事项

1. **模糊描述**
   - ❌ "代码很慢"
   - ✅ "函数 X 的 p99 延迟是 500ms，目标是 100ms"

2. **缺少约束条件**
   - ❌ "设计一个缓存"
   - ✅ "设计一个 LRU 缓存，容量 1000 项，支持并发访问"

3. **跳过验证直接实施**
   - ❌ 直接复制粘贴 Codex 的代码
   - ✅ 理解原理 → 测试验证 → 逐步实施

## 💬 常见问题

**Q: 如何选择合适的模型？**

A: 技能会根据任务描述自动选择。简单任务（代码审查、简单重构）使用 gpt-5.1-codex-max，复杂任务（算法设计、架构评审）使用 gpt-5.2。

**Q: Codex 的建议是否可以直接使用？**

A: 建议先理解原理，然后测试验证，最后逐步实施。不要盲目复制粘贴代码。

**Q: 如何提高 Codex 的输出质量？**

A: 提供完整的上下文、明确的约束条件和具体的性能要求。描述越详细，输出质量越高。

**Q: 支持哪些编程语言？**

A: Codex 支持所有主流编程语言，包括 Rust、Python、JavaScript、Go、Java 等。
